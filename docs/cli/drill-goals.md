# 演练台持续目标

运行 `/drill` 或 `/演练台`
打开本地工作台。在「持续目标工作台」填写最终结果、范围、交付文件以及每阶段的验收条件，然后选择「仅保存计划」或「创建并启动目标」。

目标使用原生 Boost 引擎：只读调查 → 按里程碑实施 → 独立复核 → 最终整体验收。目标、进度、累计用量和阶段报告按当前项目保存。完成一个阶段后继续下一个，直到完成或受阻；不把收到请求、完成部分步骤或构建通过显示为整项目完成。

## 创建与续接

```text
/goal 完成当前项目的指定功能，按要求生成交付物并只做必要验证
/goal prepare 先保存一个稍后执行的目标
/goal list
/goal status <ID>
/goal pause <ID>
/goal resume <ID>
/goal reports <ID>
```

演练台支持通用任务、深度编码、AI 写作、源码审阅、本地样本静态分析和授权 Web 演练。选择 Web 演练时须先登记演练授权并填写目标范围；选择目标类型不会扩大原有授权或自动启用免审批。

每行计划填写「阶段标题 | 验收条件」，留空采用调查、实现、验证交接三个阶段。交付文件填写工作区相对路径，用逗号分隔；默认
`DRILL-REPORT.md` 会参与最终文件哈希复核。创建的目标可由主 Agent 使用
`manage_drill_goal` 工具保存，随后在用户授权范围内调用 `run_agent_workflow`
执行。工作流中的实施者不能创建嵌套目标来绕过当前任务约束。

## 查看与控制

在「原生 Agent 任务」选择已保存目标或 Teamwork、Boost、Grill
me、Swarm 历史记录，可以查看阶段、里程碑、累计调度、独立复核范围、最近结果和失败历史，并启动或续接、暂停、导出完整报告。

暂停会请求运行中的子任务取消，保留已经写入的文件、阶段结果和累计用量。需等待子任务收尾才能续接。关闭浏览器不会关闭 CLI 或撤销工作；退出 CLI 后，在原项目重新启动，再按 ID 续接。

达到调度、失败阶段或实施轮数上限时，目标停止并保存原因。工作流预算可在详情中修改，已有累计用量不会清零，也不会因改预算自动重跑。Swarm 的专用预算仍使用原生
`/swarm budget` 命令。已完成目标的续接只返回现有结果，不再运行模型。

报告导出保存本地快照、原记录、阶段全文、哈希清单和索引；网页同时下载包含阶段全文的 JSON。超过浏览器 16
MiB 正文限额时，界面提供本地完整报告索引路径。导出不重新批准任务，也不将引用的外部工件打入报告。损坏或缺失的原报告不会用预览冒充全文。

## 现有功能

提示词与规则、供应商和模型、双语切换、六档推理强度、协作方式和并发、演练授权、免审批设置、工具巡检与保存路径、技能目录、事实和二进制工件、补丁事务及原生任务历史均继续使用原有实现。具体工具执行与审批仍在 CLI 中显示。目标不会自行修改个人密钥、授权或免审批设置。
